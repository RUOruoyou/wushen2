# 门派武学升华系统实施计划

## 1. 文档状态

- 状态：方案设计，尚未实施。
- 编写日期：2026-08-12。
- 适用范围：十二个当前可加入门派的特殊武学。
- 参考资料：
  - `docs/项目参考文件/武神传说_门派武功详解.md`
  - 当前仓库 `world/family/`、`world/skill/`、`world/extends/skill/skill.js`
- 本文只确定产品规则、技能链、数据结构、接入方式和验证标准，不代表功能已经上线。

## 2. 背景

当前特殊武学有三套相互独立的成长或组合机制：

1. 武学进阶：消耗武学进阶残页，随机三选一获得词条，并提高武学有效品质。
2. 绝招融合：历史兼容机制，通过 `ref` 为武学附加其他绝招。
3. 基础武道：基本内功、轻功、招架和武器基础技能通过武道参悟提高道阶。

现有系统可以增加面板属性和通用词条，但门派武学缺少体现本门传承的终局成长。参考资料中，武当、少林、华山、峨眉、逍遥、丐帮和杀手楼存在普通武学、门派进阶武学、上古传承之间的升级链。当前项目新增的全真、日月、明教、移花和血刀没有对应参考链，需要按当前实装技能机制补充设计。

本计划新增“升华”系统：玩家主动选择当前门派的一门合格武学，解锁该武学的门派进阶机制；部分核心武学后续可继续领悟上古传承。

## 3. 目标

1. 为十二个正式门派提供有门派辨识度的武学终局成长。
2. 升华强化技能机制、绝招联动和门派特色，不简单重复通用属性词条。
3. 保留原技能 ID、等级、经验、启用状态、进阶词条、自动出招和技能分组。
4. 让升华与现有进阶、融合、基础武道互不覆盖。
5. 所有资格、扣费、状态变更和效果计算由服务端决定。
6. 支持按门派、按武学分批实施和独立停用，不要求一次完成全部上古传承。
7. 对控制、免伤、绝对躲闪、不死、状态转移和反伤设置明确边界。

## 4. 非目标

1. 不重写现有战斗引擎。
2. 不删除或替换现有武学进阶随机词条。
3. 不把升华计入技能显示品质，不修改 `query_grade()`。
4. 不直接创建并切换到 `skillId2`、`skillId4` 技能存档。
5. 不修改玩家已有技能等级、经验、进阶词条和融合绝招。
6. 不为散人、公共武学、基础技能、知识技能、怪物技能开放升华。
7. 第一阶段不实现参考资料中的全部上古传承。
8. 不未经实战校准直接照搬参考项目的极端数值。

## 5. 名词定义

### 5.1 一阶升华

门派武学完成首次升华后获得的强化阶段，对应参考资料中的 `*2` 版本。运行时仍使用原技能 ID，`*2` 只作为策划版本标识。

### 5.2 上古传承

核心武学完成第二次升华后获得的终极阶段，对应参考资料或本文设计中的 `*4` 版本。上古传承属于后续阶段，不纳入首批上线范围。

### 5.3 源武学

玩家存档中真实存在的原始技能。例如太极剑法的源武学始终为 `taijijian`，即使完成升华，也不把存档改成 `taijijian2`。

### 5.4 参考版本 ID

策划和配置用于标识进阶版本的 ID，如 `taijijian2`。该 ID不作为玩家技能存档键，也不进入普通技能注册池。

## 6. 总体规则

### 6.1 可升华资格

一阶升华必须同时满足：

1. 操作者是玩家角色。
2. 玩家当前门派不是散人。
3. 玩家已学会目标武学。
4. 目标为 `SKILL_TYPES.SKILL`，基础品质至少绿色。
5. `skillBase.family === player.family`。
6. 目标武学位于升华配置白名单中。
7. 目标武学等级不低于2000级。
8. 目标武学已完成5重普通进阶。
9. 目标武学没有尚未选择的 `progression_offer`。
10. 当前没有执行其他会修改该技能存档的确认操作。

上古传承建议条件：

1. 已完成对应一阶升华。
2. 源武学等级不低于5000级。
3. 达成该门派的专属传承条件。
4. 消耗独立的上古传承资源。

上古条件在进入第二阶段实施前再次确认，不在首批代码中预埋不可达入口。

### 6.2 选择范围

- 玩家可以从自己当前门派的合格武学中主动选择。
- 升华按技能独立记录，不设置“全角色只能升华一门”的硬限制。
- 稀缺度由等级、5重进阶和门派功绩消耗控制。
- 不自动升华，不因达到等级或品质直接触发。

### 6.3 建议消耗

首版不新增材料对象，优先复用门派功绩，避免同时扩展掉落、商城和背包系统。

建议默认配置：

| 阶段 | 建议消耗 | 备注 |
|---|---:|---|
| 一阶升华 | 30000门派功绩 | 每门武学独立消耗 |
| 取消一阶升华 | 返还15000门派功绩 | 只返还原消耗的一半 |
| 上古传承 | 暂不开放 | 第二阶段另行确定资源来源 |

数值必须集中在配置常量中，不得散落到命令和技能脚本。正式开发前可单独调整消耗，但不能改变存档结构。

### 6.4 取消与叛师

- 已升华武学允许执行“归元”，取消最后一阶升华。
- 首版只有一阶升华，因此归元后回到未升华状态。
- 归元返还该阶实际消耗的一半，向下取整。
- 归元前必须确认背包不参与返还；功绩直接返还到玩家门派功绩字段。
- 叛师时如果存在当前门派已升华武学，沿用普通进阶的安全做法：阻止叛师并提示先归元。
- 遗忘单门武学时同样要求先归元，避免无提示损失资源。
- 后续如决定叛师自动清理，必须先明确全量退款比例并增加迁移验证，首版不采用自动清理。

### 6.5 与现有系统的关系

| 系统 | 存档字段 | 是否影响品质 | 与升华关系 |
|---|---|---:|---|
| 普通进阶 | `addin`、`addin_costs` | 是 | 升华前要求完成5重 |
| 绝招融合 | `ref` | 是 | 可与升华并存，不覆盖 |
| 基础武道 | `dao` | 否 | 只用于基础技能，与升华无关 |
| 武学升华 | `sublimation` | 否 | 独立整数阶段 |

升华不能复用 `addin`、`ref` 或 `dao`，也不能改变现有品质费用和进阶候选池。

## 7. 存档与配置设计

### 7.1 玩家技能存档

在对应技能条目上增加单个整数：

```js
me.skills[skillId].sublimation = 1;
```

约束：

- 缺失、`null`、非整数、负数统一按0处理。
- 首版只接受0或1。
- 不保存技能对象、门派对象、函数、状态对象或配置副本。
- 不保存 `referenceId`，由服务端静态配置根据源技能和阶段查询。
- 旧角色无需迁移；字段缺失自然按0处理。

### 7.2 配置注册

建议在 `world/extends/skill/sublimation.js` 注册统一配置：

```js
SKILL.SUBLIMATION_CONFIG = {
    taijijian: {
        family: "WUDANG",
        ranks: {
            1: {
                referenceId: "taijijian2",
                name: "太极剑法",
                level: 2000,
                progressionSteps: 5,
                meritCost: 30000
            }
        }
    }
};
```

配置只保存稳定元数据。具体绝招效果由源技能脚本或同目录门派扩展读取升华阶段后执行，避免在配置中保存大量运行时闭包。

### 7.3 公共接口

建议新增：

```js
SKILL.prototype.query_sublimation_rank(me)
SKILL.prototype.query_sublimation_config(rank)
SKILL.prototype.can_sublimate(me, rank)
SKILL.prototype.query_sublimation_desc(me)
SKILL.prototype.is_sublimated(me, rank)
```

角色辅助接口：

```js
CHARACTER.prototype.query_skill_sublimation(skillId)
```

接口必须处理NPC、缺失技能、异常存档和热更新后的旧实例。

## 8. 服务端流程

### 8.1 命令

新增命令：

```text
shenghua <skillId>
shenghua <skillId> confirm
shenghua <skillId> remove
shenghua <skillId> removeok
```

建议命令属性：

- `allow_fight = false`
- 不允许死亡、忙乱或处于不可安全修改技能状态时执行。
- NPC侍从暂不开放升华；若后续开放，必须通过 `dc` 路径单独评估存档与资源归属。

### 8.2 升华事务

确认升华时按以下顺序执行：

1. 重新读取技能和玩家状态，不信任第一次打开面板时的数据。
2. 再次校验门派、技能等级、5重进阶、当前阶段和门派功绩。
3. 记录旧技能评分和旧升华阶段。
4. 释放当前技能附加属性。
5. 扣除门派功绩。
6. 写入 `skillItem.sublimation = 1`。
7. 重新附加技能属性并重算角色。
8. 更新技能评分。
9. 保存角色，保存原因为 `skill-sublimation`。
10. 刷新技能详情、技能列表和功绩显示。

任一步异常必须恢复旧阶段和功绩，并重新初始化角色属性。不能出现扣费成功但升华未生效，或升华生效但未扣费。

### 8.3 归元事务

1. 校验当前阶段和退款值。
2. 记录旧状态。
3. 释放技能属性。
4. 删除或归零 `sublimation`。
5. 返还一半实际功绩消耗。
6. 重新附加属性、重算、更新评分并保存。
7. 刷新技能详情和功绩显示。

后续若开放多阶，必须保存各阶实际消耗，不能用当前配置倒推出历史退款。首版只有固定一阶消耗，可以不增加成本数组；开放第二阶前必须先扩展为可追溯成本字段。

## 9. 前端交互

### 9.1 技能详情入口

`checkskill` 响应建议增加：

```js
{
    can_sublimation: 1,
    sublimation_rank: 0,
    sublimation_name: "北斗七星剑"
}
```

技能详情底部按条件显示：

```text
进阶　融合　升华　遗忘
```

已完成升华时按钮文案改为“升华详情”。

### 9.2 升华面板

面板至少显示：

- 当前武学和当前升华阶段；
- 目标进阶武学名称；
- 解锁的被动与绝招变化；
- 等级、进阶重数和门派要求；
- 当前门派功绩与本次消耗；
- 确认升华按钮；
- 已升华时显示归元说明和退款数额。

服务端发送独立 `sublimation` 消息，不复用 `progression_offer`。前端可以复用现有技能进阶面板的容器和按钮样式，但状态字段必须分开。

### 9.3 移动端要求

- 390px宽度下技能说明、条件和按钮不得横向溢出。
- 768px布局下升华面板不能遮挡技能说明和底部操作。
- 长绝招说明需要自然换行，按钮保持可点击高度。
- 重复打开、关闭或切换技能不能累积事件监听。

### 10.2 全真教

门派定位：阵法协同、星位连携、持续防御、稳步叠加。

| 源武学 | 一阶武学 | 参考ID |
|---|---|---|
| 天罡剑法 | 北斗七星剑 | `qixingjian2` |
| 先天功 | 先天无极功 | `xiantiangong2` |
| 重阳神掌 | 重阳真掌 | `chongyangshenzhang2` |
| 北斗阵法 | 天罡北斗阵 | `beidouzhen2` |

上古传承：先天大道，`xiantiangong4`。

#### 北斗七星剑

- 七星拱月按有效阵位攻击5至7次，每剑忽视12%防御。
- 命中后留下对应层数星位；至少5剑命中时，目标命中和躲闪降低12%，持续8秒。
- 七星绝命剑消耗全部星位，攻击 `4 + floor(星位/2)` 次，最高7次。
- 每层星位增加每剑4%伤害和2%破防；满7层时最后一剑不可招架。

#### 先天无极功

- 先天无极劲持续25秒，增加24%防御、24%伤害减免和武学等级×8的临时气血，每5秒恢复2%最大内力。
- 一炁归元恢复15%最大气血、10%最大内力，解除忙乱并清除一个普通负面状态，冷却45秒。

#### 重阳真掌

- 阳关三叠保留逐掌强化；三掌全中后使目标防御和招架降低15%，持续8秒。
- 重阳返照持续12秒，命中获得返照层数，每层增加5%伤害和命中，最多3层；结束时每层恢复2%最大气血。

#### 天罡北斗阵

- 每处星位提供2%防御、1%伤害减免和固定招架。
- 4星额外提供10%控制抵抗。
- 7星额外提供10%命中和10%最终伤害。
- 非全真且未掌握阵法的队友只获得一半效果。

## 12. 数值边界

### 12.1 一阶升华

- 单体多段绝招总理论倍率建议控制在400%至700%。
- 常驻或长持续增益控制在20%至30%。
- 高强度增益持续10至20秒。
- 对玩家的普通忙乱、昏迷、禁绝招等强控制单次不超过5秒。
- NPC可以使用较长控制，但必须受现有异常抵抗影响。
- 同一技能不能同时提供高额伤害、高额免伤、稳定控制和无代价恢复。
- 吸血、回气按实际伤害或最大属性设置双重上限。
- 多次反击、减冷却和状态触发必须有内置冷却。

### 12.2 上古传承

- 每门派只保留一条核心上古链。
- 强机制冷却原则上不低于60秒。
- 不死、绝对躲闪、免控、伤害返还、状态交换每次施展限制触发次数。
- 不允许循环触发反伤、反击或状态转移。
- 不允许复制任务状态、场景状态、死亡状态和不可移除状态。

## 16. 风险与控制

### 16.1 强度叠加

普通进阶已经提供最多25%基础属性增益，门派套装、装备、经脉和基础武道还会继续叠加。升华优先改变机制，不统一增加全部基础属性。

### 16.2 控制链

忙乱、昏迷、禁绝招、无法防御和不可躲闪可能形成连续控制。所有强控制需要玩家目标上限、异常抵抗和内置冷却。

### 16.3 伤害循环

反击、反伤、吸血和额外攻击必须使用已有 `no_append`、`no_append_target` 或独立临时冷却，防止双方无限互相触发。

### 16.4 热更新

对共享技能对象做函数包装时容易重复包装。优先使用幂等标记或直接在源技能逻辑中查询阶段；涉及统一原型方法时必须重启验证。

### 16.5 参考资料差异

参考资料来自另一套实时数据，当前项目战斗属性、技能等级和装备强度不同。参考资料用于确定机制和命名，数值必须按当前项目校准。

### 16.6 存档兼容

首版使用整数阶段，旧存档无迁移。开放第二阶和多阶退款前必须增加实际成本记录，不能静默改变既有退款结果。
