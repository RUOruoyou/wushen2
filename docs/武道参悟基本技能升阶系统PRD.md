# 武道参悟 · 基本技能升阶系统 PRD

## 1. 文档信息

- 状态：P0 通用框架、P1 剑道垂直切片与 P2 九类扩展已完成并部署
- 适用对象：玩家角色
- 不包含：NPC、怪物和随从的自动升阶；如需开放，另行设计权限、消耗和存档迁移
- 资源消耗：`book/wudao`（武道）
- 基础技能范围：仅以下 10 个 `SKILL_TYPES.BASE` 技能

## 2. 目标与边界

玩家消耗武道，对已学会的基础技能进行永久升阶。升阶后，基础技能获得对应的道名、等级上限、专属被动和道招式，同时继续使用原基础技能 ID，保证特殊武学的装备关系和存档字段兼容。

本系统不改变特殊技能现有的“进阶”（`lingwu`）和“融合”（`lingwu2`）规则。两套系统使用不同的字段、命令和配置，不得互相覆盖。

## 4. 核心规则

1. 只有玩家已经拥有的基础技能可以升阶；未学会、未知 ID、特殊技能和知识技能均拒绝。
2. 阶位为 `0-5`，初始为 `0`。阶位只增不减，不提供玩家退款、重置或撤销入口。
3. 每次只升一阶，必须满足目标阶位的等级要求并一次性扣除对应数量的武道。
4. 武道扣除必须发生在所有校验通过之后。扣除失败时不得修改技能、属性或等级上限。
5. 升阶后基础技能 ID 不变，例如 `sword` 仍然是 `sword`，特殊技能仍可装备到 `sword` 上。
6. 技能展示名称按角色当前阶位动态计算，不能修改全局技能对象的静态 `name`。
7. 每个基础技能独立计算等级上限。某一技能升阶不会提高其他技能的上限。
8. 已有角色没有 `dao` 字段时按 `0` 读取；字段必须限制为整数 `0-5`，异常值记录日志并按 `0` 处理。

## 5. 阶位配置

“武道消耗”是本次升阶的增量消耗，不是累计消耗。单个基础技能升满共消耗 `1 + 10 + 20 + 50 + 100 = 181` 本武道。

| 阶位 | 阶位名称 | 升阶所需技能等级 | 等级上限增加 | 本阶武道消耗 | 累计主加成 | 道招式 |
|------|---------|----------------|-------------|-------------|-----------|--------|
| 0 | 基础技能原名 | - | `0` | - | `0%` | - |
| 1 | `X道·初悟` | `1000` | `+200` | `1` | `+5%` | 有 |
| 2 | `X道·通明` | `1500` | `+400` | `10` | `+10%` | 无 |
| 3 | `X道·归一` | `2000` | `+600` | `20` | `+15%` | 有 |
| 4 | `X道·无相` | `2500` | `+800` | `50` | `+20%` | 无 |
| 5 | `X道·真解` | `3000` | `+1000` | `100` | `+25%` | 有 |

升阶要求是“当前技能等级大于等于要求值”。例如技能等级为 `1500` 时可以升到二阶，但不能直接跳到三阶。

## 6. 等级上限规则

新增按技能计算的接口：

```text
me.query_skill_limit(skillId)
```

计算规则：

```text
query_skill_limit(skillId) = me.skill_limit() + dao * 200
```

其中 `dao` 是 `me.skills[skillId].dao`。无参数的 `me.skill_limit()` 保留原有行为，供旧代码和角色境界逻辑使用。

以下场景必须使用 `query_skill_limit(skillId)`：

- `study` 学习
- `xue` 请教
- `lianxi` 练习
- 学习/练习队列的下一项
- 技能面板的上限展示
- 管理员或测试工具对技能等级的边界检查

升阶不会自动提升当前技能等级，不会返还潜能，也不会改变已经获得的技能经验。

## 7. 属性计算规则

### 7.1 主加成作用范围

- 剑、拳、鞭、暗器、杖、棍、刀的主加成只作用于当前攻击使用的对应基础类型。
- 主加成包含该基础类型的普通攻击和该类型的道招式。
- 已装备的特殊武学绝招是否继承主加成，由该绝招的 `daoAffected` 配置决定，默认继承。
- 不影响其他基础类型攻击、反震、队友伤害和没有攻击来源的环境伤害。
- 暴击、破防、伤害减免的结算顺序保持现有战斗顺序；主加成作为对应类型的最终伤害百分比加成，只计算一次。

### 7.2 非攻击属性

| 道 | 属性规则 |
|----|---------|
| 气道 | 累计增加最大气血百分比；升阶后重新 `recount`，不按比例补当前气血 |
| 身道 | 累计增加自身躲闪百分比；攻击间隔减少 `150ms`，最低不低于引擎允许的 `500ms` |
| 御道 | 累计增加自身防御百分比 |
| 杖道·通明 | 根骨百分比加成，按角色最终根骨计算一次，不写入永久基础属性 |
| 杖道·无相 | 最大气血百分比额外增加 `8%` |

百分比属性必须通过统一的道属性计算接口提供，不能把同一加成同时写入 `prop` 和战斗临时状态，避免重复计算。

## 9. 道招式通用规范

每个道招式配置必须包含以下字段，未配置完整不得上线：

| 字段 | 说明 |
|------|------|
| `id` | 稳定 ID，格式建议为 `<baseId>.dao.<key>` |
| `required_dao` | 最低道阶，必须与阶位配置一致 |
| `mp` | 基础内力消耗，需明确是否受气道减免 |
| `release_time` | 出招时间，单位毫秒 |
| `distime` | 冷却时间，单位毫秒 |
| `use_type` | 战斗中、非战斗或两者均可 |
| `weapon_type` | 所需武器类型；不需要武器时明确为空 |
| `auto_allowed` | 是否允许加入自动出招 |
| `target_rule` | 单目标、周围目标或自身；多目标数量必须固定 |
| `damage_rule` | 伤害基准、倍率、破防和暴击计算顺序 |
| `status_rule` | 状态 ID、持续时间、叠层、覆盖和可驱散规则 |

默认允许道招式与已装备的特殊武学绝招共存。基础技能道招式使用基础技能等级计算；特殊武学绝招继续使用特殊技能等级计算。二者使用不同的冷却 ID，不得互相覆盖。

## 10. 存档与属性更新

技能存档结构：

```javascript
me.skills[baseId] = {
    level: 1000,
    exp: 0,
    dao: 1,
    enable_skill: "special_skill_id"
};
```

升级时必须执行：

1. 校验技能类型、当前阶位、等级要求、武道数量和角色状态。
2. 扣除武道并确认扣除成功。
3. 更新 `dao` 字段。
4. 释放旧阶位属性，重新附加新阶位属性。
5. 执行 `init_skill()` 和 `recount()`。
6. 刷新技能名称、技能描述、等级上限和道招式列表。
7. 保存角色数据。

升阶不改变 `enable_skill`，不删除特殊技能，不改变基础技能 ID。升级过程中发生异常时，必须保证武道、`dao` 和属性状态不会出现半完成结果。

## 11. 命令与前端交互

### 11.1 命令

新增独立命令 `dao`，不占用现有 `lingwu` 和 `lingwu2`：

```text
dao                         查看可升阶的基础技能
dao <baseId>                查看该技能当前阶位、消耗和效果
dao <baseId> up             确认升阶
```

命令限制：

- `allow_fight = false`
- 死亡、昏迷、战斗和真实动作忙碌状态禁止操作
- 只接受本 PRD 的 10 个基础技能 ID
- 玩家不能通过客户端伪造阶位、消耗或技能 ID

`book/wudao` 保留现有“领悟”和“融合”动作，新增“参悟”入口调用 `dao`，不得改变已有两个动作的含义。

### 11.2 技能面板

`checkskill` 和 `cha` 返回以下字段：

```text
dao
dao_name
dao_next
dao_cost
dao_required_level
dao_level_limit
can_dao
```

技能详情页显示：

- 当前道名和阶位；
- 当前等级、升阶后等级上限；
- 下一阶等级要求和武道数量；
- 当前已生效的累计属性；
- 下一阶新增被动和道招式；
- “不可撤销”提示。

技能列表只显示技能名称、当前等级和经验进度，不显示“道阶/上限”冗余字段；独立等级上限仅在技能详情和参悟确认面板中展示。

升级成功后必须刷新技能列表、技能描述、等级上限、战斗绝招按钮和自动出招配置。若道招式尚未达到最低阶位，不得显示为可用。

## 12. 配置与实现边界

所有名称、阶位、消耗、等级要求、属性和招式放入统一配置，不在命令脚本中复制数值。

建议配置形态：

```text
DAO_CONFIG[baseId] = {
    displayName,
    rankNames,
    requiredLevel: [0, 1000, 1500, 2000, 2500, 3000],
    cost: [0, 1, 10, 20, 50, 100],
    levelBonus: [0, 200, 400, 600, 800, 1000],
    passiveByRank,
    performByRank
}
```

实现优先放在 `world/extends/`：

- 基础技能道配置和名称计算：`world/extends/skill/`；
- 升阶命令：`world/cmd/skill/dao.js`；
- 基础技能上限调用点：`world/cmd/skill/`；
- 战斗触发、状态和按基础类型的伤害范围：`world/extends/char/`；
- 前端技能面板：`src/dialog/skills.js`。

不得通过运行时修改全局 `SKILL.name` 或共享 `pfm` 对象来保存玩家阶位。

## 13. 验收标准

### 13.1 升阶和存档

- 10 个基础技能均能从 0 升到 5 阶；`bite` 没有入口。
- 等级不足、武道不足、战斗中、忙碌中、未知技能和重复提交均被拒绝。
- 每阶扣除数量准确，单个技能升满总消耗为 181 本。
- 旧角色没有 `dao` 字段时正常登录并按 0 阶运行。
- 重登录、重启服务后 `dao`、名称、属性和等级上限保持一致。
- 升阶不会清除特殊技能装备关系或已有技能经验。

### 13.2 名称、上限和属性

- 同一技能不同角色可以同时显示不同道名，不能互相污染。
- 每个基础技能只提升自己的等级上限。
- 主加成只作用于对应基础类型，不影响其他类型和反震伤害。
- 气血、防御、躲闪、攻击间隔和百分比加成在 0 阶、1 阶、5 阶下均符合配置。
- 升阶后重新计算属性不会重复附加或遗留旧属性。

### 13.3 道招式

- 未达到阶位时不可释放，也不显示为可用自动招式。
- 已装备特殊武学时，道招式仍可按独立 ID 释放，特殊武学绝招仍可正常释放。
- 内力不足、武器不符、目标无效、冷却中和不允许战斗场景均有明确失败提示。
- 多段攻击、控制、不可招架、不可闪避、不可释放绝招等效果按配置生效。
- 状态到期、死亡、离开战斗和重登录后不会残留临时效果。

### 13.4 前端

- 768px 桌面布局和 390px 手机布局均能查看阶位和升级入口。
- 升级确认、武道数量不足、等级不足和不可撤销提示清晰。
- 升级成功后技能列表、描述和绝招按钮即时更新。
