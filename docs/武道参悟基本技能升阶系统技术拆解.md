## 3. 数据模型与配置契约

### 3.1 角色存档

只在已有基础技能条目上增加字段，不改变技能 ID、装备字段和特殊武学字段：

```javascript
me.skills.sword = {
    level: 1000,
    exp: 0,
    dao: 1,
    enable_skill: "special_skill_id"
};
```

规则：

1. 只允许十个基础技能 ID 使用 `dao`：`force`、`dodge`、`parry`、`sword`、`unarmed`、`whip`、`throwing`、`staff`、`club`、`blade`。
2. `dao` 必须经过 `Number`、整数和 `0-5` 范围校验。缺失按 0；异常值记录一次服务端日志并按 0 运行。
3. 规范化函数必须是唯一入口，名称、上限、属性和命令都调用该入口，不能各自读取原始字段。
4. 不为旧角色批量写回字段。角色成功升阶时才写入 `dao`，避免无必要的存档变更。
5. NPC、怪物和随从即使存在同名字段，也默认按 0 处理；一期命令必须额外校验 `me.is_player`。

### 3.2 配置注册

配置挂在已有 `SKILL` 命名空间上，避免在动态执行的世界脚本之间依赖局部变量：

```javascript
SKILL.DAO_CONFIG["sword"] = {
    displayName: "剑道",
    rankNames: ["基本剑法", "剑道·初悟", "剑道·通明", "剑道·归一", "剑道·无相", "剑道·真解"],
    requiredLevel: [0, 1000, 1500, 2000, 2500, 3000],
    cost: [0, 1, 10, 20, 50, 100],
    levelBonus: [0, 200, 400, 600, 800, 1000],
    passiveByRank: {},
    performByRank: {}
};
```

字段约束：

- 四个数组长度固定为 6，索引就是道阶；启动时检查长度、数值和阶位名称。
- `passiveByRank` 只描述本阶新增效果，查询时累计 1 到当前阶。
- `performByRank` 的 key 使用 `dao.<key>`，外部释放格式为 `perform <baseId>.dao.<key>`。
- 引擎生成的内部 PFM ID 继续遵循现有 `<skillId>/<pid>` 形式，例如 `sword/dao.po`；不能另造一套冷却字段。
- 每个道招式必须有 `required_dao`、`mp`、`release_time`、`distime`、`use_type`、`weapon_type`、`auto_allowed`、`target_rule`、`damage_rule` 和 `status_rule`。

## 4. 通用方法拆解

以下方法优先放入 `world/extends/skill/skill.js`，通过原型扩展覆盖所有角色：

| 方法 | 责任 |
| --- | --- |
| `SKILL.prototype.query_dao_rank(me)` | 返回规范化后的当前阶位；非十类基础技能返回 0 |
| `SKILL.prototype.query_dao_config()` | 返回当前基础技能的配置；未知 ID 返回空 |
| `SKILL.prototype.query_dao_name(me, rank)` | 按角色阶位返回显示名称，不写入全局 `SKILL.name` |
| `SKILL.prototype.query_dao_next(me)` | 返回下一阶、等级要求、消耗、上限和新增效果 |
| `SKILL.prototype.query_dao_level_limit(me)` | `me.skill_limit() + dao * 200` |
| `SKILL.prototype.can_dao(me)` | 校验角色、技能类型、当前阶位和下一级是否存在；只做无副作用判断 |
| `SKILL.prototype.query_dao_passives(me)` | 汇总当前阶位已经生效的被动配置 |
| `SKILL.prototype.query_dao_performs(me)` | 返回已达到阶位且可供手动/自动出招的道招式 |
| `CHARACTER.prototype.query_skill_limit(skillId)` | 对外提供按技能计算的上限；非参悟技能回退到 `skill_limit()` |

动态名称必须同时覆盖以下输出路径：

1. `SKILL.query_color_name(me)` 和 `SKILL.query_desc(me, lv)` 的服务端文案；
2. `SKILL.item_to_json()` 返回的 `name`；
3. `lingwu`、`lingwu2` 完成后发送的技能刷新消息；
4. `cha`、`checkskill`、学习、练习和战斗失败提示。

不得修改基础技能脚本的全局 `name`，也不得把角色阶位写入共享的 `color_name`。

## 5. 升阶命令与事务顺序

新增 `world/cmd/skill/dao.js`：

```text
dao
dao <baseId>
dao <baseId> up
```

命令配置：

- `allow_fight = false`；保持默认禁止昏迷、状态和忙乱操作；
- 只接受十个基础技能 ID；
- 一期只允许玩家角色；
- `up` 每次只升一级，重复提交按当前阶位重新校验，不能跳阶或重复扣费。

### 5.1 查询流程

1. 解析 `baseId`，通过白名单和 `SKILL.DAO_CONFIG` 校验。
2. 检查角色是否已学会该基础技能。
3. 读取规范化阶位，组装当前效果和下一阶信息。
4. `dao <baseId>` 优先返回 `progression` 消息，复用现有技能详情面板；无面板时返回中文文本。
5. `dao` 无参数只列出已学会且仍可升阶的基础技能。

### 5.2 升阶流程

所有可能失败的检查必须先完成，再扣除武道：

1. 校验玩家、非死亡/昏迷/战斗/忙碌/其他状态、技能类型和技能存在性。
2. 校验当前阶位小于 5，目标阶位等级要求满足，且角色持有足够 `book/wudao`。
3. 按当前建议使用存档原始 `skillItem.level` 校验等级，不允许通过 `query_prop(baseId)` 的临时等级绕过门槛；若产品决定允许临时属性，必须同步修改本步骤和验收用例。
4. 使用 `me.remove_obj(page, cost)` 扣除武道，并确认返回值成功。
5. 在内存中把 `skillItem.dao` 更新为目标阶位，执行 `me.init_skill()` 和 `me.recount()`。
6. 刷新技能列表、技能描述、技能等级上限、手动绝招列表和自动绝招配置。
7. 保存角色数据并发送成功提示。

扣除成功后若属性刷新抛出异常，必须恢复旧 `dao` 并尝试返还武道，同时记录包含角色 ID、技能 ID和目标阶位的服务端错误；客户端不能收到“升级成功”。

## 6. 等级上限接入点

`query_skill_limit(skillId)` 是新增的唯一按技能上限接口，下面的旧调用必须替换：

| 文件 | 当前用途 | 替换规则 |
| --- | --- | --- |
| `world/cmd/skill/study.js` | 读书开始、读书过程中和读书完成检查 | 基础技能调用 `me.query_skill_limit(skill.id)` |
| `world/cmd/skill/xue.js` | 请教目标上限、队列目标和每次学习检查 | 基础技能调用学生自己的 `me.query_skill_limit(skill.id)` |
| `world/cmd/skill/lianxi.js` | 练习目标、队列目标和每次练习检查 | 基础技能调用 `me.query_skill_limit(skill.id)` |
| `world/cmd/dialog/cha.js` | 技能面板全局标题 | 保留全局 `skill_limit()`，每项由 `item_to_json` 输出 `dao_level_limit` |
| `src/dialog/skills.js` | 单项技能显示 | 列表显示等级/经验；独立上限仅在技能详情和参悟面板显示，不生成“道阶/上限”冗余提示 |

学习/练习队列中保存的 `max_level` 仍然是玩家当时选择的目标；实际执行每一跳都必须再次经过 `query_skill_limit`，防止升阶后队列越界。

## 7. 属性和战斗钩子

### 7.1 属性层

可直接复用现有属性字段的效果，通过 `attach_prop` / `release_prop` 管理，并在升阶前后成对刷新。攻击类型限定、剑法暴击、杖道根骨百分比等效果不能直接写成全局属性，应通过道上下文计算。

建议的上下文对象：

```javascript
{
    baseId: "sword",
    pfm: pfmItem || null,
    isDao: true,
    daoAffected: true,
    par: attackParam
}
```

### 7.2 普通攻击和道招式

普通攻击和大多数特殊武学最终都会进入 `world/extends/char/combat.js` 的 `do_attack`。在命中、招架、暴击和 `damage()` 之前建立 `baseId`，按 `daoAffected` 只计算一次对应基础技能的主加成。

必须覆盖：

- 剑、拳、鞭、暗器、杖、棍、刀的对应武器/无武器攻击；
- 这些类型的特殊武学绝招（默认受影响，可由 PFM 配置关闭）；
- 多段道招式的每一段攻击。

必须排除：

- 其他基础类型攻击；
- 反震、环境伤害和没有攻击来源的 `damage()` 直接调用；
- 已经计算过主加成的二次路径。

### 7.3 现有属性字段映射

以下映射可以作为实现基线，但涉及攻击类型限定的项目仍需按上下文处理：

| PRD 效果 | 现有字段/钩子 | 备注 |
| --- | --- | --- |
| 气血百分比 | `hp_per` + `USER.recount()` | 升阶后 `recount`，不按比例补当前气血 |
| 躲闪百分比 | `ds_per` + `recount` | 只对自身生效 |
| 防御百分比 | `fy_per` + `recount` | 只对自身生效 |
| 命中、暴击、招架 | `mz_per`、`bj_per`、`zj_per` | 剑法/暗器等类型限定不得直接使用全局字段 |
| 忽视防御、伤害减免 | `diff_fy_per`、`diff_sh_per` | 由 `damage()` 现有结算顺序处理 |
| 攻击间隔减少 150ms | `gjsd`，最低由 `recount` 保持 500ms | 不能误用 `releasetime` 或 `distime` |
| 绝招内力消耗 | `expend_mp_per` 或 PFM 专属键 | 只影响释放者的 `PERFORM.query_mp()` |
| 杖道根骨百分比 | 新增道专用计算钩子 | 当前没有通用 `con_per`，不能伪装成永久根骨 |

## 8. 道招式与特殊武学共存

现有 `perform` 在 `resolve_perform()` 中会优先解析基础技能当前装备的特殊武学。因此道招式必须增加明确分支：

1. `pfmid` 以 `dao.` 开头时，从 `SKILL.get(baseId)` 解析，不从 `enable_skill` 解析。
2. 普通特殊武学和融合绝招继续走现有分支。
3. 道招式等级使用基础技能等级；融合绝招仍使用特殊技能等级和半级规则。
4. 冷却 key 使用现有 `pfm/<baseId>/<pid>` 形式；道招式和特殊武学 PID 不得相同。
5. `world/cmd/skill/auto_pfm.js`、`CHARACTER.init_pfms()` 和 `USER.on_skillchanged()` 必须使用同一个 `query_dao_performs()` 结果，避免手动按钮、自动配置和服务器自动战斗列表不一致。
6. 道招式未达到 `required_dao` 时不进入自动配置，也不能通过伪造命令释放。

### P2 冻结项

进入 P2 编码前必须冻结以下协议，否则只允许写测试夹具，不允许上线配置：

1. `dao_<base>_<key>` 状态的 `override`、叠层上限、刷新和可驱散规则。
2. 多目标筛选范围、目标死亡后的后续段数和房间跨区域边界。
3. 控制免疫与现有 `no_busy`、`no_dodge`、`no_parry` 属性的优先级。
4. 致命保留、绝对闪避和不可招架之间的结算顺序。
5. 杖道根骨百分比的最终计算入口，以及攻防转化是否影响暴击和反震。

## 11. P0 技术决策清单

以下事项必须在写入战斗代码前确认：

1. 主加成在 `do_attack` 完成武器、技能、暴击和 `power_gj` 汇总后、目标防御结算前应用；通过 `dao_base_id` 和 `dao_damage_applied` 保证同一攻击上下文只计算一次，反震和显式 `dao_affected:false` 路径排除。
2. 升阶门槛使用存档原始 `skillItem.level`，装备临时技能等级不能绕过门槛。
3. 对应类型上下文字段固定为 `dao_base_id` 和 `dao_affected`；普通攻击从武器类型推导，道招式显式声明基础类型。
4. 杖道根骨百分比在 `USER.recount()` 中以临时有效根骨参与气血、防御计算，不写入 `con` 或存档，避免循环放大。
5. 剑道凌虚使用现有状态系统的 `dao_sword_lingxu` 状态 ID，覆盖模式为 `2`，持续时间结束由状态系统回收。
6. 道招式外部 PID 固定使用 `dao.<key>`，当前剑道 PID 为 `dao.pofeng`、`dao.lingxu`、`dao.zhenjie`；后续不得改名，否则会影响自动出招配置和存档。
